# 디자인 규칙 (색상 · 글자 크기 · 레이아웃)

작성일: 2026-08-11
작성자: ui-ux-expert

이 문서는 성적관리 웹사이트의 **모든 화면이 따라야 하는 디자인 규칙을 관리하는 단 하나의 문서**다.
색상 코드나 글자 크기 값은 이 문서에만 정의하고, 컴포넌트 코드에는 값을 직접 적지 않는다.
컴포넌트에서는 아래 "CSS 변수 / Tailwind 매핑" 절에 정의된 이름(변수·클래스)만 참조한다.

새로운 색이나 글자 크기가 필요하면, 컴포넌트에 값을 바로 넣지 말고 **이 문서에 규칙을 추가한 뒤** 그 규칙만 가져다 쓴다.

---

## 0. 디자인 컨셉 요약

- 참고 레이아웃: [TailAdmin 무료 대시보드](https://nextjs-free-demo.tailadmin.com/) 스타일의 **왼쪽 사이드바 + 상단바** 관리자 화면 구조.
- **라이트(화이트) 테마 / 다크 테마 둘 다 지원**하며, 사용자가 상단바 버튼으로 언제든 전환할 수 있다.
- 브랜드 포인트 컬러는 **부드러운 파스텔 핑크**. 화려함보다 **가독성과 사용 편의성**이 먼저다.
  - 버튼처럼 "눌러야 하는" 핵심 요소는 진한 핑크 + 흰 글자로 대비를 확실히 확보한다.
  - 배지, 밑줄, 아이콘처럼 "장식/보조" 요소에는 더 연한 파스텔 핑크를 쓴다.
- 전체적으로 **모서리를 둥글게, 그림자는 은은하게, 여백은 넉넉하게** 주는 모던 SaaS 카드형 레이아웃을 따른다.
- 실제 사용자는 개발자가 아닌 교무처 직원이므로, 화면에 보이는 모든 문구(버튼, 안내, 에러)는 어려운 말 없이 쉬운 한글로 쓰고 "다음에 무엇을 하면 되는지"까지 함께 알려준다.

## 1. 색상 팔레트

### 1-1. 색상 설계 원칙

- 본문 글자와 배경의 명도 차이(대비)는 최소 **4.5 : 1** 이상을 기본 기준으로 삼는다(작은 글자 기준, WCAG AA).
- 파스텔 핑크는 3단계로 나눠 쓴다.
  1. **포인트 배경용 파스텔 핑크**(가장 연함, 50~200단계) — 카드 강조 배경, 뱃지 배경, 선택된 행 배경 등.
  2. **강조 아이콘/장식용 핑크**(500단계) — 아이콘, 그래프 포인트, 탭 밑줄 등 배경 없이 단독으로 쓰는 곳.
  3. **버튼/링크용 진한 핑크**(600~700단계) — 실제로 눌러야 하는 버튼, 링크, 강조 텍스트. 흰 글자와 대비 4.5:1 이상을 확보한 색만 사용한다.
- 성공/경고/오류/안내 색은 핑크 브랜드 색과 헷갈리지 않도록 각각 초록/노랑/빨강/파랑 계열을 그대로 쓴다.

### 1-5. 테마 전환 방법(개발 참고)

- `<html>` 태그에 `class="dark"` 를 붙이는 **class 전략**을 사용한다(Tailwind v4 `@custom-variant dark`).
- 상단바에 해/달 아이콘 버튼을 두어 라이트 ↔ 다크를 전환하고, 선택한 테마는 브라우저(localStorage)에 저장해 다음 접속 때도 유지한다.
- 사용자의 시스템 설정(prefers-color-scheme)은 최초 방문 시 기본값으로만 참고하고, 이후에는 사용자가 직접 고른 값을 우선한다.

## 2. 글자 크기 규칙

### 2-1. 폰트

- 기본 폰트는 프로젝트에 이미 적용된 `Geist Sans`(본문), `Geist Mono`(숫자/코드성 데이터, 예: 학번)를 그대로 사용한다.
- 숫자가 나열되는 표(점수, 학번, 총점 등)는 자릿수가 흔들리지 않도록 `Geist Mono` 사용을 권장한다.

### 2-2. 크기 단계

| 단계 | 이름 | 모바일 | PC(md 이상) | 굵기 | 용도 |
|---|---|---|---|---|---|
| 1 | 페이지 제목 | `text-2xl`(24px) | `text-3xl`(30px) | `font-bold` | 화면 맨 위 큰 제목 (예: "성적입력") |
| 2 | 섹션 제목 | `text-xl`(20px) | `text-2xl`(24px) | `font-semibold` | 화면 안 구역 제목 (예: "이상값 검사 결과") |
| 3 | 카드/소제목 | `text-lg`(18px) | `text-lg`(18px) | `font-semibold` | 카드 제목, 모달 제목 |
| 4 | 본문 | `text-base`(16px) | `text-base`(16px) | `font-normal` | 일반 설명, 표 내용, 입력칸 글자 |
| 5 | 보조 설명 | `text-sm`(14px) | `text-sm`(14px) | `font-normal` | 캡션, 도움말, 표 아래 부가 설명 |
| 6 | 아주 작은 라벨 | `text-xs`(12px) | `text-xs`(12px) | `font-medium` | 뱃지, 태그, 날짜/시간 표시 |
| - | 버튼 글자 | `text-sm`(14px) | `text-base`(16px) | `font-medium` | 모든 버튼 공통 |

- 줄 간격(line-height)은 제목류는 `leading-tight`, 본문·설명류는 `leading-relaxed`를 기본으로 한다.
- 표(성적 목록 등)처럼 정보 밀도가 높은 화면은 본문이라도 `text-sm`을 허용하되, 절대 `text-xs` 아래로는 내려가지 않는다(교무처 직원이 읽기 편해야 하므로).

## 3. 레이아웃 규칙

### 3-1. 전체 구조

```
┌───────────────────────────────────────────┐
│               상단바 (Topbar)               │  높이 64px, 화면 상단에 고정(sticky)
├───────────┬─────────────────────────────────┤
│           │                                 │
│  사이드바  │           본문 콘텐츠            │
│ (Sidebar) │           (Content)             │
│           │                                 │
└───────────┴─────────────────────────────────┘
```

- **사이드바**: 로고, 메뉴(대시보드/수강과목 관리/성적관리/기준정보관리), 하위 메뉴로 구성.
- **상단바**: 왼쪽에 햄버거 버튼(모바일/태블릿에서만) + 현재 화면 이름, 오른쪽에 라이트/다크 전환 버튼 + 로그인한 직원 이름 + 로그아웃.

### 3-2. 반응형 기준(Tailwind 기본 breakpoint 사용)

| 구간 | 기준 폭 | 사이드바 동작 |
|---|---|---|
| 모바일 | `< md` (768px 미만) | 사이드바는 기본적으로 **숨김**. 상단바의 햄버거(☰) 버튼을 누르면 사이드바가 화면 왼쪽에서 **오버레이(덮임)로 슬라이드 인**되고, 뒤 배경은 반투명 어두운 dim 처리. 바깥 영역을 탭하거나 X 버튼을 누르면 닫힌다. |
| 태블릿 | `md ~ lg` (768px~1023px) | 사이드바를 **아이콘만 보이는 좁은 폭(80px)**으로 기본 노출. 필요하면 펼쳐서 임시로 넓게 볼 수 있다. |
| PC | `≥ lg` (1024px 이상) | 사이드바를 **글자까지 보이는 넓은 폭(260px)**으로 항상 고정 노출. 사용자가 원하면 접기 버튼으로 80px 아이콘 전용 모드로 줄일 수 있다(선택 기능). |

- 사이드바 폭: 펼침 260px(`w-64` 근사), 접힘 80px(`w-20`).
- 본문 콘텐츠 안쪽 여백(padding): 모바일 `p-4`(16px), 태블릿 `p-6`(24px), PC `p-8`(32px).
- 카드/통계 묶음은 `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` (필요 시 `xl:grid-cols-4`), 카드 사이 간격은 `gap-4`(모바일) ~ `gap-6`(PC).
- 표(성적 목록, 수강과목 목록 등)는 화면이 좁을 때 가로 스크롤(`overflow-x-auto`)을 허용해 표 형태를 유지한다. 컬럼이 너무 많아 모바일에서 읽기 어려우면 핵심 컬럼(이름, 총점, 등급 등)만 먼저 보여주고 나머지는 상세보기에서 확인하게 한다.

### 3-3. 로그인 화면(예외)

- 로그인 화면은 사이드바/상단바 없이 화면 중앙에 카드(아이디/비밀번호/로그인 버튼)만 배치한다.
- 모바일에서는 카드 폭 100%(좌우 여백 `px-4`), PC에서는 카드 최대 폭 `max-w-sm`(384px) 정도로 중앙 정렬한다.

## 4. 모서리 · 그림자 · 여백 (모던 스타일 기본값)

### 4-1. 모서리 둥글기(border-radius)

| 이름 | 값 | 용도 |
|---|---|---|
| radius-sm | `8px` (`rounded-lg`) | 뱃지, 태그, 입력칸 안쪽 작은 요소 |
| radius-md | `12px` (`rounded-xl`) | 버튼, 입력칸, 기본 카드 |
| radius-lg | `16px` (`rounded-2xl`) | 모달, 큰 패널, 사이드바 메뉴 항목 |
| radius-full | `9999px` (`rounded-full`) | 아바타, 원형 아이콘 버튼, 필/토글 |

### 4-2. 그림자(box-shadow)

| 이름 | 라이트 테마 값 | 다크 테마 값 | 용도 |
|---|---|---|---|
| shadow-sm | `0 1px 2px rgba(36,28,36,0.06)` | `0 1px 2px rgba(0,0,0,0.4)` | 입력칸, 얇은 카드 기본 그림자 |
| shadow-md | `0 4px 14px rgba(201,63,115,0.10)` | `0 4px 14px rgba(0,0,0,0.45)` | 기본 카드, hover 상태 |
| shadow-lg | `0 12px 32px rgba(201,63,115,0.14)` | `0 12px 32px rgba(0,0,0,0.55)` | 모달, 드롭다운, 오버레이 사이드바 |

- 라이트 테마는 그림자에 브랜드 핑크를 살짝 섞어(rgba 안의 색을 pink-600 기준으로) 은은한 파스텔 느낌을 준다.
- 다크 테마는 배경이 이미 어두우므로 색을 섞지 않고 순수 검정 그림자를 더 진하게 써서 층을 구분한다.

### 4-3. 여백(spacing)

- 8px를 기본 단위로 하는 간격만 사용한다: `4, 8, 12, 16, 20, 24, 32, 40, 48px` (Tailwind `1, 2, 3, 4, 5, 6, 8, 10, 12`).
- 카드 내부 여백: 기본 `p-6`(24px), 모바일에서는 `p-4`(16px)까지 허용.
- 섹션과 섹션 사이 간격: `space-y-6`~`space-y-8`.
- 입력 폼에서 항목과 항목 사이 간격: `space-y-4`(16px).
- 버튼 안쪽 여백: `px-4 py-2`(기본), 중요 버튼(저장 등)은 `px-6 py-2.5`로 살짝 크게.

## 5. 저장 · 삭제 확인창(다이얼로그) 규칙

프로젝트 규칙상 저장·삭제 같은 되돌리기 어려운 동작 전에는 반드시 확인창을 띄운다. 확인창도 아래 색·문구 규칙을 따른다.

- 확인창은 모달로 띄우고, 뒤 배경은 `rgba(0,0,0,0.4)`로 어둡게 처리(dim)한다.
- **저장 확인창**: 제목 예) "저장할까요?", 설명 예) "지금까지 입력한 내용이 저장돼요." 버튼은 `[아니요, 취소]`(연한 버튼, 테두리만) / `[예, 저장할게요]`(기본 버튼 색 pink-600 + 흰 글자).
- **삭제 확인창**: 제목에 지울 대상을 분명히 적는다. 예) "'국어교육과' 학과를 삭제할까요?", 설명 예) "삭제하면 되돌릴 수 없어요." 버튼은 `[취소]`(연한 버튼) / `[삭제할게요]`(오류 색 `#C81E3A`(라이트) / `#F2617A`(다크) 배경 + 흰 글자, "destructive" 버튼).
- 확인창의 모든 문구는 쉬운 한글로 쓰고, 실행 결과가 무엇인지 한 줄로 미리 알려준다.

## 7. 문구 작성 원칙 (참고)

색과 크기 외에, 화면에 보이는 모든 텍스트는 다음을 지킨다(프로젝트 공통 규칙 재확인용).

- 전문 용어 대신 쉬운 한글로 쓴다. (예: "Invalid input" ❌ → "입력한 값을 확인해 주세요" ⭕)
- 에러/안내 메시지는 "무엇이 문제인지" + "다음에 무엇을 하면 되는지"를 함께 쓴다.
  - 예) "이름을 입력해 주세요." (X, 다음 행동이 약함) → "학생 이름을 입력한 뒤 다시 검색해 주세요." (O)
- 버튼 문구는 동사로 명확하게 끝맺는다. (예: "확인" 대신 "저장하기", "삭제하기", "엑셀 업로드하기")
