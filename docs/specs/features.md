# 성적관리 웹사이트 기능 명세서

작성일: 2026-08-11
작성자: requirements-analyst

이 문서는 대학 성적관리 웹사이트 전체 화면에 대한 기능 명세서다. 이 서비스의 실제 사용자는 대학 교무처 직원 **김똘미**이며, 학생들의 중간고사, 기말고사, 과제점수 결과를 받아 각 등급 및 총점 등을 엑셀로 관리해왔다. 이를 대체할 성적관리 웹사이트를 만드는 것이 이번 프로젝트의 목적이다. 백엔드는 이미 완성되어 운영 중이며, API 기준은 Swagger(http://lecture.s-mart.kr/api)다.

> 참고: 요구사항 원문에 등장한 "김학사"는 오타이며, CLAUDE.md의 "김똘미(교무처 직원)"와 동일 인물이다. 이 문서 전체에서 사용자는 "김똘미(교무처 직원)"로 통일한다.

---

## 로그인

### 개요
김똘미(교무처 직원)가 아이디와 비밀번호를 입력해 본인 인증을 거쳐 성적관리 웹사이트에 들어갈 수 있게 하는 화면이다.

### 배경/목적
성적 정보는 민감한 개인정보(학생 점수, 등급)를 포함하므로, 아무나 접근하지 못하도록 로그인 절차가 필요하다. 기존에는 엑셀 파일로 관리해 접근 통제가 담당자 PC 보안에 의존했지만, 웹사이트로 전환하면서 별도의 인증 절차가 필요해졌다.

### 상세 요구사항
- **화면 구성**: 아이디 입력칸, 비밀번호 입력칸, 로그인 버튼으로 구성한다.
- 김똘미는 아이디 입력칸과 비밀번호 입력칸에 각각 값을 입력하고 로그인 버튼을 눌러 로그인을 시도한다.
- **로그인 성공 시**: 대시보드 화면으로 이동한다.
- **로그인 실패 시**: 실패 이유를 한글로 화면에 보여주고, 다음에 무엇을 하면 되는지(예: "아이디와 비밀번호를 다시 확인한 뒤 입력해 주세요", "아이디를 다시 확인해 주세요" 등)까지 함께 안내한다.
- 아이디 또는 비밀번호 입력칸을 비운 채 로그인 버튼을 누르면, 서버에 요청을 보내기 전에 어떤 칸을 채워야 하는지 한글로 안내한다.
- 로그인하지 않은 상태로 대시보드/수강과목 관리/성적관리/기준정보관리 등 내부 화면에 직접 접근을 시도하면 로그인 화면으로 이동시킨다.

### 범위 밖
- 회원가입(계정 생성) 화면 포함 여부: 확인 필요 (백엔드에서 이미 계정을 발급해주는 방식인지, 웹사이트에서 자체 가입을 지원하는지 불명확)
- 비밀번호 찾기/재설정 기능 포함 여부: 확인 필요

### 확인 필요
- **Swagger 확인 결과**: requirements-analyst 역할에는 웹 조회(WebFetch) 도구가 주어지지 않아, 이번 작성 시점에는 http://lecture.s-mart.kr/api 의 로그인 관련 엔드포인트(요청 필드명, 응답 형태, 에러 코드/메시지 등)를 직접 확인하지 못했다. 화면 구성(아이디/비밀번호/로그인 버튼)과 성공 시 대시보드 이동, 실패 시 한글 사유+다음 행동 안내는 이번 지시대로 명세에 반영했으나, 아래 항목은 design-architect 단계에서 Swagger를 직접 조회해 반드시 확정해야 한다.
  - 로그인 요청 시 실제 필드명(예: `username`/`id`/`loginId`, `password` 등)과 HTTP 메서드/경로.
  - 로그인 성공 응답의 형태(토큰 필드명, 사용자 정보 포함 여부 등).
  - 로그인 실패 시 서버가 내려주는 에러 코드/메시지 종류(아이디 없음, 비밀번호 불일치, 계정 잠김 등 케이스별 구분이 있는지)와 이를 한글 안내 문구로 어떻게 매핑할지.
  - 아이디/비밀번호 방식 외에 다른 인증 방식(SSO 등)이 실제로 존재하는지 여부.
- 인증 토큰 저장 방식(세션 쿠키 vs JWT 등)은 위 Swagger 확인 이후 design-architect 단계에서 정할 사항이다.
- 권한/역할 구분이 있는지(예: 교무처 직원 외 다른 역할(관리자/조회자 등)이 있는지)가 불명확하다. 현재까지 파악된 바로는 사용자가 김똘미(교무처 직원) 한 명/역할이지만, 여러 역할이 존재할 가능성은 열려 있다.
- 로그인 유지 시간(자동 로그아웃 정책) 여부도 확인 필요.

### 완료 조건
- 아이디와 비밀번호를 올바르게 입력하고 로그인 버튼을 누르면 대시보드 화면이 보인다.
- 아이디나 비밀번호를 잘못 입력하고 로그인 버튼을 누르면 실패 이유와 다음 행동 안내(예: "아이디와 비밀번호를 다시 확인해 주세요")가 한글로 보인다.
- 아이디 또는 비밀번호 칸을 비운 채 로그인 버튼을 누르면 어떤 칸을 채워야 하는지 안내하는 문구가 보인다.
- 로그인하지 않은 상태에서 대시보드 등 내부 페이지 주소로 바로 접속하면 로그인 화면이 보인다.
- 로그인에 성공하고 다시 접속(새로고침)해도 로그아웃 처리되지 않고 대시보드 화면이 계속 보인다. (확인 필요: 세션 유지 정책에 따라 조건이 달라질 수 있음)

## 대시보드

### 개요
로그인 직후 진입하는 첫 화면으로, 김똘미(교무처 직원)가 매일 로그인할 때마다 학과·강의·성적 등록 현황과 전체 성적 통계(평균 총점, 평균 평점, 등급 분포 등)를 한눈에 빠르게 파악할 수 있도록 요약 정보를 보여주는 화면이다.

### 배경/목적
기존 엑셀 관리 방식에서는 전체 현황을 파악하려면 여러 파일을 열어 일일이 확인해야 했다. 웹사이트에서는 김똘미가 매일 로그인 후 바로 "지금 학과/강의/성적이 몇 건이나 등록되어 있는지", "전체 평균은 어느 정도인지", "등급은 어떻게 분포되어 있는지"를 별도 조회 없이 확인할 수 있어야 업무 효율이 올라간다. 이 화면은 백엔드 API `GET /dashboard/summary`가 내려주는 데이터를 그대로 활용해 구성한다.

### 상세 요구사항

**데이터 출처**: 대시보드에 표시되는 모든 수치는 `GET /dashboard/summary` API의 응답을 사용한다(Swagger로 확인 완료). 응답에 포함된 필드는 다음과 같다.
- `totalDepartments`: 등록된 학과 수
- `totalLectures`: 등록된 강의 수
- `totalStudentScores`: 등록된 성적 건수
- `averageTotalScore`: 전체 성적의 평균 합계점수
- `averageGpa`: 전체 평균 평점(GPA, 4.5 만점)
- `gradeDistribution`: 등급별 분포 배열
- `departmentStats`: 학과별 통계 배열
- `lectureStats`: 강의별 통계 배열
- `termStats`: 학기별 통계 배열

**① 로그인 및 진입**
- 로그인에 성공하면 자동으로 대시보드 화면으로 이동한다.
- 대시보드 화면에 들어오면(또는 새로고침하면) `GET /dashboard/summary`를 호출해 최신 데이터를 불러와 화면을 채운다.

**② 요약 카드 (핵심 지표 한눈에 보기)**
- 화면 상단에 다음 다섯 가지 값을 각각 하나의 카드로 보여준다: 등록된 학과 수(`totalDepartments`), 등록된 강의 수(`totalLectures`), 등록된 성적 건수(`totalStudentScores`), 평균 총점(`averageTotalScore`), 평균 평점(`averageGpa`, 4.5 만점 기준임을 함께 표기).
- 각 카드에는 값과 함께 무엇을 의미하는 값인지 알 수 있는 한글 이름(예: "등록 학과 수", "평균 평점(4.5 만점)")을 붙인다.
- 데이터가 아직 없거나(예: 성적이 하나도 등록되지 않은 초기 상태) 값이 비어 있을 때는 "0" 또는 "등록된 데이터가 없습니다" 등 알아보기 쉬운 형태로 보여준다(정확한 처리 방식은 design-architect 단계에서 확정).

**③ 등급 분포**
- `gradeDistribution`(등급별 인원 또는 비율 배열)을 활용해 A/B/C/D/F 등 등급별 분포를 그래프(막대그래프 또는 원그래프 등) 또는 표 형태로 보여준다.
- 각 등급의 인원수와 전체 대비 비율(%)을 함께 확인할 수 있어야 한다.
- 그래프로 만들지 표로만 만들지는 ui-ux-expert/frontend-developer 단계에서 화면 구현 난이도와 라이브러리 상황을 고려해 정하되, 최소한 등급별 인원/비율 정보는 반드시 보여야 한다.

**④ 학과별 / 강의별 / 학기별 통계 (1차 범위: 간단한 표)**
- `departmentStats`(학과별 통계), `lectureStats`(강의별 통계), `termStats`(학기별 통계)를 각각 별도의 간단한 표로 보여준다.
- 이번 1차 범위에서는 각 표에 학과명/강의명/학기명과 API가 내려주는 통계값(예: 평균 점수, 인원수 등 응답에 포함된 항목)을 그대로 나열하는 수준으로만 구현한다. 정렬, 검색, 필터, 그래프화 등 고급 기능은 포함하지 않는다.
- 각 표 위에는 "학과별 통계", "강의별 통계", "학기별 통계"와 같이 무엇에 대한 표인지 알 수 있는 한글 제목을 붙인다.

**⑤ 메뉴 진입점**
- 대시보드에서 주요 메뉴(수강과목 관리, 성적관리, 기준정보관리)로 이동할 수 있는 진입점(메뉴/버튼/카드)이 있다.

### 범위 밖
- 학과별/강의별/학기별 통계를 클릭해 상세 분석(예: 특정 학과를 눌러 학과 내 강의별 세부 현황을 파고드는 화면, 기간별 추이 그래프 등)을 보여주는 기능은 이번 1차 범위에 포함하지 않는다. 이는 추후 별도 기능(상세 분석 화면)으로 확장할 수 있다.
- 학과별/강의별/학기별 표에 대한 검색, 정렬, 페이지네이션, 엑셀 다운로드 기능은 이번 1차 범위에 포함하지 않는다.
- 대시보드 수치를 특정 학기/기간으로 필터링해서 보는 기능은 이번 1차 범위에 포함하지 않는다(범위 포함 여부는 확인 필요 항목 참고).

### 확인 필요
- `gradeDistribution`, `departmentStats`, `lectureStats`, `termStats` 각 배열 안의 정확한 필드명(예: 학과별 통계 안에 학과명, 평균점수, 인원수 등 어떤 키로 내려오는지)은 이번 요구사항 정리 단계에서는 "등급별/학과별/강의별/학기별 통계"라는 항목 존재만 확인되었고 세부 필드까지는 확정되지 않았다. design-architect 단계에서 Swagger 응답 예시를 다시 확인해 표의 정확한 컬럼을 정해야 한다.
- 대시보드에 표시할 수치가 실시간 데이터인지, 특정 학기 기준 데이터인지(즉 `termStats`와 별개로 상단 요약 카드 수치가 전체 기간 누적인지 특정 학기 기준인지) 확인 필요.
- 등급 분포를 그래프로 표현할지 표로만 표현할지는 확인 필요(둘 다 완료 조건을 만족할 수 있으므로 화면 구현 단계에서 결정).
- 데이터가 없는 초기 상태(학과/강의/성적이 하나도 없는 경우) 화면에 무엇을 보여줄지 구체적인 문구는 확인 필요.

### 완료 조건
- 로그인에 성공하면 대시보드 화면이 보인다.
- 대시보드에 들어가면 학과 수·강의 수·성적 건수·평균 총점·평균 평점이 카드로 보인다.
- 대시보드에 들어가면 등급별 분포가 그래프(또는 표)로 보인다.
- 대시보드에 들어가면 학과별/강의별/학기별 통계가 각각 표로 보인다.
- 대시보드에서 수강과목 관리 메뉴를 누르면 수강과목 목록 화면으로 이동한 화면이 보인다.
- 대시보드에서 성적관리 메뉴를 누르면 성적입력 또는 성적조회 화면으로 이동한 화면이 보인다.

## 수강과목 관리

### 개요
학기별로 개설된 수강과목을 목록으로 확인하고, 새로운 수강과목을 등록할 수 있는 화면 그룹이다. "목록"과 "생성" 두 개의 하위 화면(또는 하나의 화면 내 목록+등록 폼)으로 구성된다.

### 배경/목적
성적을 입력하려면 먼저 어떤 과목이 개설되어 있는지가 시스템에 등록되어 있어야 한다. 기존 엑셀 방식에서는 과목별로 파일을 따로 만들었지만, 웹사이트에서는 과목을 시스템에 등록해두고 그 과목 단위로 성적을 관리한다.

### 상세 요구사항 - 목록
- 등록된 수강과목을 목록 형태로 조회할 수 있다.
- 목록에는 과목명, 담당(교수/학과 등 확인 필요) 등 과목을 식별할 수 있는 정보가 표시된다.
- 목록에서 특정 과목을 선택하면 상세 정보를 확인하거나 성적관리 화면으로 이동할 수 있다. (연결 방식은 확인 필요)

### 상세 요구사항 - 생성
- 김똘미가 새로운 수강과목 정보를 입력하고 저장하면 목록에 새 과목이 추가된다.
- 필수 입력 항목이 비어있는 상태로 저장을 시도하면 안내 메시지가 표시되고 저장되지 않는다.
- 저장 성공 시 김똘미는 저장이 완료되었음을 알 수 있는 안내를 받는다.

### 범위 밖
- 수강과목 수정/삭제 기능 포함 여부: 확인 필요 (발화에는 "목록", "생성"만 언급되어 있고 수정/삭제는 언급되지 않음)

### 확인 필요
- 수강과목 등록 시 어떤 항목을 입력해야 하는지(과목명, 학과, 학년, 학기, 담당교수, 수강정원 등)가 명시되지 않았다. Swagger의 과목 생성 API 스펙 확인이 필요하다.
- 목록 화면에 검색/필터 기능이 필요한지 여부(발화에는 언급 없음).
- 수강과목과 학과관리(기준정보관리)의 관계(과목 등록 시 학과를 선택하는 구조인지) 확인 필요.

### 완료 조건
- 수강과목 관리 메뉴에서 목록 화면에 들어가면 등록된 수강과목들이 목록으로 보인다.
- 새 수강과목 정보를 모두 입력하고 저장하면 방금 등록한 과목이 목록에 추가되어 보인다.
- 필수 항목을 비워둔 채 저장을 누르면 무엇을 채워야 하는지 안내하는 메시지가 보인다.

## 성적관리 - 성적입력(엑셀)

### 개요
중간고사, 기말고사, 과제 점수가 담긴 엑셀 파일을 업로드하면, 업로드한 학생들의 성적을 표로 미리 확인하고, 이상한 값을 자동으로 검사하고, 등급을 자동 계산한 뒤, 사용자가 최종 확인 후 저장할 수 있는 화면이다.

### 배경/목적
기존 업무 방식이 엑셀 기반이었으므로, 김똘미가 이미 작성한 엑셀 파일을 그대로 업로드해 성적을 등록할 수 있게 하면 업무 전환 부담이 줄어든다. 다만 엑셀에는 입력 실수(빈 칸, 100점 초과 등)나 등급 분포 이상(특정 등급 쏠림)이 생길 수 있으므로, 저장하기 전에 미리보기와 자동 검사를 거쳐 실수를 미리 걸러내기 위한 기능이다.

### 상세 요구사항 (업로드~저장 흐름)
1. **① 엑셀 파일 업로드**: 김똘미는 정해진 형식의 엑셀 파일을 선택해 업로드한다.
2. **② 미리보기 표시**: 업로드한 파일 안의 학생 데이터(예: 50명)가 화면에 표 형태로 미리 보인다. 아직 서버에 저장되기 전 단계이며, 김똘미는 이 표를 보고 내용을 확인한다.
3. **③ 이상값 자동 검사**: 미리보기 표에서 다음과 같은 이상한 값을 자동으로 검사하고, 문제가 있는 칸(행/열)을 화면에서 눈에 띄게 표시한다.
   - 점수 칸이 비어 있는 경우(빈 칸).
   - 점수가 100점을 넘거나 0점 미만 등 있을 수 없는 값인 경우.
   - 그 밖에 형식에 맞지 않는 값(예: 숫자가 아닌 문자가 들어간 경우) — 세부 규칙은 확인 필요.
4. **④ 등급 자동 계산**: 이상값이 없는(또는 검사를 통과한) 학생들에 대해, 중간고사/기말고사/과제 점수로 총점을 계산하고, 학점환산기준에 따라 등급(A+, A, B+ 등)을 자동으로 계산해 미리보기 표에 함께 보여준다.
5. **⑤ 등급 분포(A등급 비율) 표시**: 전체 학생 중 A등급(A+ 및 A를 포함하는 범위인지 여부는 확인 필요)의 비율을 계산해 화면에 보여준다. 만약 A등급 비율이 30%를 넘으면, "A등급 비율이 30%를 초과했습니다" 등 그 사실을 김똘미가 알아볼 수 있도록 화면에 명확히 표시한다.
6. **⑥ 저장**: 미리보기 화면에는 저장 버튼이 있다. 저장 버튼을 누르면 즉시 저장되지 않고, 먼저 "정말 저장할까요?"와 같은 확인창이 뜬다. 김똘미가 확인창에서 승인(예/저장)을 눌러야만 실제 저장(서버 반영)이 진행된다. 확인창에서 취소를 누르면 저장이 진행되지 않고 미리보기 화면으로 돌아온다.
7. 이상값이 있는 학생이 포함된 상태에서 저장을 시도할 경우 어떻게 처리할지(전체 저장 차단 vs 이상값 학생만 제외하고 저장 등)는 확인 필요.
8. 저장이 완료되면 저장 결과(성공/실패 건수 등)를 사용자에게 안내한다.

### 범위 밖
- 성적 개별 수정(엑셀 없이 화면에서 직접 한 명씩 수정하는 기능) 포함 여부: 확인 필요
- 미리보기 표에서 셀 값을 직접 고쳐서 저장하는 기능(엑셀 재업로드 없이 화면에서 바로 수정) 포함 여부: 확인 필요

### 확인 필요
- **Swagger 확인 결과**: requirements-analyst 역할에는 웹 조회(WebFetch) 도구가 주어지지 않아, http://lecture.s-mart.kr/api 의 성적 업로드/저장 관련 엔드포인트(요청 형식, 응답 형식, 에러 케이스)를 이번 작성 시점에는 직접 확인하지 못했다. design-architect 단계에서 반드시 Swagger를 조회해 아래 항목을 확정해야 한다.
  - 성적 업로드 API가 엑셀 파일을 그대로 받는지, 아니면 프론트에서 엑셀을 파싱한 JSON 데이터를 보내는지.
  - 미리보기 단계(저장 전 임시 확인)를 지원하는 별도 API가 있는지, 아니면 프론트에서만 엑셀을 파싱해 미리보기를 구현하고 실제 저장 시에만 API를 호출하는 구조인지.
  - 저장 성공/실패 응답 형식과, 일부 학생만 실패했을 때의 응답 형식.
- **엑셀 파일의 정확한 컬럼 구성**: 발화와 일반적인 성적 관리 관행으로 미루어 학번, 이름, 학과, 중간고사 점수, 기말고사 점수, 과제 점수 등이 포함될 것으로 추정되나, 정확한 컬럼명·순서·형식은 확정되지 않았다. Swagger 및 실제 사용 중인 엑셀 양식 확인이 필요하다.
- **등급 산정 기준(총점 계산식)**: 중간고사/기말고사/과제 점수를 각각 몇 %씩 반영해 총점을 계산하는지(예: 중간 30% + 기말 40% + 과제 30%)가 확정되지 않았다.
- **학점환산기준의 구체적 계산식**: 총점 구간별로 어떤 등급(A+, A, B+, B, C+, C, D+, D, F 등)을 부여하는지 구체적인 점수 구간이 확정되지 않았다. 이 규칙은 "기준정보관리 - 학점환산기준 관리" 화면에서 관리하는 값을 그대로 가져와 계산에 사용하는 구조로 예상되나, 실제 연동 방식(저장된 기준값을 어떤 API로 가져오는지)은 확인 필요.
- **A등급 비율 계산 기준**: "A등급"의 범위가 A+와 A를 모두 포함하는지, A만 의미하는지 확인 필요. 30%라는 기준값이 시스템에 고정값인지, 학점환산기준 관리 화면에서 설정 가능한 값인지도 확인 필요.
- 이상값 검사 항목이 "빈 칸"과 "100점 초과(또는 0점 미만)" 외에 추가로 필요한지(예: 학번 형식 오류, 중복 학번 등) 확인 필요.
- 이상값이 있는 상태에서 저장 버튼을 눌렀을 때의 처리 방식(저장 자체를 막을지, 이상값 학생만 제외하고 나머지만 저장할지) 확인 필요.

### 완료 조건
- 엑셀 파일을 업로드하면 학생 50명의 데이터가 표로 보인다.
- 빈 칸이나 100점을 넘는 값이 있으면 해당 칸에 이상 표시가 보인다.
- 미리보기 표에 각 학생의 총점과 등급이 자동으로 계산되어 보인다.
- A등급 비율이 30%를 넘으면 그 사실이 화면에 보인다.
- 저장 버튼을 누르면 "정말 저장할까요?" 확인창이 먼저 보인다.
- 확인창에서 승인을 누르면 저장이 완료되었다는 안내가 보이고, 취소를 누르면 저장되지 않고 미리보기 화면이 계속 보인다.

## 성적관리 - 성적조회 및 엑셀다운로드

### 개요
입력된 학생 성적을 이름, 학과 등으로 검색하여 조회하고, 조회 결과를 엑셀 파일로 내려받을 수 있는 화면이다.

### 배경/목적
성적을 입력한 뒤에는 특정 학생이나 학과 단위로 성적을 확인하거나, 외부 보고/보관 등의 목적으로 엑셀로 추출할 필요가 있다. 기존 엑셀 관리 습관을 반영해 결과물도 엑셀로 받을 수 있게 한다.

### 상세 요구사항
- 김똘미는 학생 이름으로 성적을 검색할 수 있다.
- 김똘미는 학과로 성적을 검색(필터링)할 수 있다.
- 검색 결과는 목록 형태로 표시되며, 각 학생의 중간고사/기말고사/과제 점수, 총점, 등급 등이 함께 보인다.
- 검색 결과가 없을 경우, 결과가 없다는 안내가 표시된다.
- 김똘미는 현재 조회된 목록(또는 전체 목록)을 엑셀 파일로 다운로드할 수 있다.

### 범위 밖
- 성적조회 화면에서 점수를 직접 수정하는 기능 포함 여부: 확인 필요

### 확인 필요
- 이름/학과 검색 외 추가 검색 조건(과목, 학년, 학기 등)이 필요한지 확인 필요.
- 엑셀 다운로드 시 포함되는 컬럼 구성이 성적입력용 엑셀 양식과 동일한지, 다른 양식인지 확인 필요.
- 등급 산정 기준(중간/기말/과제 반영 비율, 등급 구간)은 성적입력 화면과 공통으로 확인이 필요한 사항이다.

### 완료 조건
- 학생 이름을 입력해 검색하면 해당 이름과 일치하는 학생의 성적이 목록에 보인다.
- 학과를 선택해 검색하면 해당 학과 학생들의 성적만 목록에 보인다.
- 검색 결과 화면에서 엑셀다운로드 버튼을 누르면 조회된 성적이 담긴 엑셀 파일이 다운로드된다.

## 기준정보관리 - 학과관리

### 개요
성적관리 시스템에서 사용할 학과 정보를 등록/조회하고 관리하는 화면이다.

### 배경/목적
학생 성적을 학과별로 검색하고 분류하려면 시스템에 학과 정보가 기준 데이터로 먼저 등록되어 있어야 한다. 학과 정보는 수강과목 등록, 성적조회 검색 등 여러 화면에서 공통으로 참조되는 기준 정보다.

### 상세 요구사항
- 등록된 학과 목록을 조회할 수 있다.
- 김똘미가 새로운 학과 정보를 등록할 수 있다.
- 학과 정보를 수정할 수 있는지 여부는 확인 필요.
- 학과 정보를 삭제할 수 있는지 여부는 확인 필요.

### 범위 밖
- 학과 수정/삭제 기능: 발화에 명시되지 않아 확인 필요 (포함될 가능성이 높으나 확정 전까지 범위 밖으로 표기)

### 확인 필요
- 학과관리 화면에서 등록/조회 외에 수정, 삭제 기능이 필요한지 확인 필요.
- 학과 등록 시 필요한 입력 항목(학과명, 학과코드, 단과대학 등)이 무엇인지 확인 필요.

### 완료 조건
- 기준정보관리의 학과관리 화면에 들어가면 등록된 학과 목록이 보인다.
- 새 학과 이름(및 필요한 정보)을 입력하고 저장하면 목록에 새 학과가 추가되어 보인다.
- 이미 등록된 학과명을 중복으로 등록하려고 하면 중복 안내 메시지가 보인다. (확인 필요: 중복 등록 제한 정책 여부)

## 기준정보관리 - 학점환산기준 관리

### 개요
점수(총점)를 등급(예: A+, A, B+ 등)으로 환산하는 기준을 등록/관리하는 화면이다.

### 배경/목적
학생의 중간고사, 기말고사, 과제 점수로 계산된 총점을 등급으로 변환하려면 점수 구간별 등급 기준이 시스템에 정의되어 있어야 한다. 이 기준은 성적입력/성적조회 시 등급을 자동 계산하는 데 사용되는 핵심 기준 정보다.

### 상세 요구사항
- 현재 설정된 학점환산기준(점수 구간별 등급)을 조회할 수 있다.
- 김똘미가 학점환산기준을 새로 등록하거나 수정할 수 있다.
- 저장된 학점환산기준은 성적입력/조회 시 등급 자동 계산에 반영된다.

### 범위 밖
- 학기별/과목별로 다른 학점환산기준을 적용하는 기능 포함 여부: 확인 필요 (하나의 공통 기준만 사용하는지, 여러 기준을 관리할 수 있는지 불명확)

### 확인 필요
- 학점환산기준의 구체적인 규칙(예: 95점 이상 A+, 90점 이상 A 등 구간과 등급 목록)이 명시되지 않았다.
- 중간고사/기말고사/과제 점수의 총점 반영 비율 자체도 학점환산기준 관리 화면에서 설정하는 항목인지, 별도 기준인지 확인 필요.
- 학점환산기준이 하나만 존재하는지, 학과/학년/학기별로 여러 기준을 관리할 수 있어야 하는지 확인 필요.
- A등급 비율 30% 초과 여부를 표시하는 성적입력 화면 기능과 연동해, "A등급 비율 상한 30%"와 같은 값이 이 화면에서 설정 가능한 항목인지도 확인 필요.

### 완료 조건
- 기준정보관리의 학점환산기준 관리 화면에 들어가면 현재 설정된 점수 구간별 등급 기준이 보인다.
- 점수 구간과 등급을 입력하고 저장하면 변경된 기준이 화면에 반영되어 보인다.
- 학점환산기준을 저장한 뒤 성적입력/성적조회 화면에서 새 기준에 따라 계산된 등급이 보인다.

## 전체 확인 필요 사항 요약

1. 로그인 API의 실제 요청/응답 형식과 에러 케이스(본 문서 작성 시점에는 WebFetch 도구가 없어 Swagger를 직접 확인하지 못했음. design-architect 단계에서 반드시 확인 필요).
2. 권한/역할 구분 존재 여부(김똘미 외 다른 역할이 있는지).
3. 대시보드에 표시할 구체적인 정보/통계 항목.
4. 등급 산정 기준: 중간고사/기말고사/과제 점수 반영 비율(총점 계산식).
5. 학점환산기준의 구체적 점수 구간-등급 규칙, 그리고 기준이 단일한지 여러 개인지 여부.
6. 성적입력용 엑셀 파일의 정확한 컬럼 구성(양식).
7. 성적입력 화면의 업로드/미리보기/저장 API 동작 방식(엑셀을 서버가 직접 받는지, 프론트에서 파싱 후 JSON으로 보내는지 등) — Swagger 미확인.
8. 이상값 검사 항목의 전체 범위(빈 칸, 100점 초과 외 추가 항목 여부)와 이상값 존재 시 저장 처리 방식.
9. A등급 비율 계산 기준(A+/A 포함 범위)과 30% 기준값이 고정값인지 설정 가능한 값인지 여부.
10. 수강과목 등록 시 필요한 입력 항목, 수정/삭제 기능 포함 여부.
11. 학과관리의 수정/삭제 기능 포함 여부 및 등록 항목.
12. 성적조회 시 이름/학과 외 추가 검색 조건 필요 여부, 엑셀 다운로드 양식.
13. 대시보드 `gradeDistribution`/`departmentStats`/`lectureStats`/`termStats` 각 배열의 정확한 필드 구성(학과명/강의명/학기명 외 어떤 통계값이 포함되는지) — design-architect 단계에서 Swagger 응답 예시로 확정 필요.
